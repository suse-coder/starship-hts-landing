## Environment: what restarts the OpenCode server (2026-11-21)

- Not memory: 31 GB available, no swap in use, cgroup OOM-kill counter 0, no memory pressure.
- CPU: 12 cores, load 12–15 over 15 minutes, CPU pressure averaged 20 % over 5 minutes.
- Mechanism (`~/.local/share/opencode/log/opencode.log`): the client logs "Event stream stalled" (20 times today) and then restarts `opencode serve --service`. A restart starts five `rea mcp` processes (one per project directory, about 275 MB RSS and 5–8 % CPU each) plus the browse MCP. They take 25–40 s to connect, and the server answers HTTP 503 meanwhile, so the next stall can follow. Today's restarts cluster at 06:03, 08:23–08:28, 08:50–08:54 and 09:09.
- Triggers in this session: headless Chromium with software WebGL (all cores for minutes), mission runs (one core each for 1–2 min), and dev server, tests and screenshot runs running in parallel with subagents.
- Second factor: `opencode.db` is 828 MB (plus a 17 MB WAL). Synchronous reads of large sessions can block the event loop, and the VS Code server helpers add CPU bursts.
- Rules from now on: heavy commands run under `nice -n 19`; one headless browser at a time; no parallel mission runs.

## Fourth round — visible bugs, tiles and Q25 (2026-11-21, afternoon)

### Landing still used cold gas (R11c)

- Root cause: the flip/landing/terminal command spread the phase `base`, whose `useRcs` is `true`, and the
  gimbal allocator was capped at the cold-gas roll authority. Every torque the gimbal did not realise went
  to the RCS, so the landing looked like it was steering on thrusters.
- Fix: `useRcs: false` from flip ignition onward, and `allocateGimbals` gets `Infinity` when the RCS is off,
  so the gimbal takes the full three-axis torque.
- Evidence: mission at 144 t, N₂ 3333 kg at the flip and unchanged to impact. The puffs are also low-passed
  in the view (below), so a firing jet no longer blinks.

### Stars painted over the Earth

- Root cause: three.js draws transparent objects after opaque ones. The starfield was transparent, and the
  Earth writes no depth near the surface (so local objects draw over it), so the stars were drawn last and
  appeared on top of the planet.
- Fix: the stars are opaque (renderOrder −9, before the Earth), and the altitude fade scales the material
  colour instead of the opacity. `.tmp/shots/verify/orbit.png` shows stars only above the limb.

### White flicker at T+30:29.9

- Root cause 1: the plasma shader used a 5-octave fBm scrolling at 6 units/s. At 60 fps the highest octave
  moved about one cycle per frame, aliasing into white where the additive plasma crossed the bloom
  threshold (2.5).
- Root cause 2: the cold-gas puffs set their opacity directly from the 25 Hz RCS duty, so a pulsing roll
  jet blinked white at frame rate.
- Fix: 3-octave, slower noise, a smaller noise contribution to intensity, and a soft knee below the bloom
  threshold; RCS opacity low-passed (~80 ms) with a softer colour and a 0.5 cap.
- Measured at the exact T+30:29.9: white pixels 0.15 % (was 3 % before the first pass), mean luminance
  116.8 → 119.4 smoothly over 20 frames. No jumps.
